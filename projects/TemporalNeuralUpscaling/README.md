# TemporalNeuralUpscaling

A staged on-device AI engineering project that builds a real-time 2x neural-upscaling pipeline for Android and studies its complete CPU/GPU/NPU cost.

> Status: Phases 1-4 are complete. The static model lowers to one SM8550/HTP v73 FP16 `QnnBackend` delegate with no portable fallback and executes successfully through the QNN HTP runtime on the physical Snapdragon 8 Gen 2 phone.

## Current Pipeline

```text
Low-resolution RGB tensor (NCHW, float32)
  -> Lightweight spatial SR model
  -> High-resolution RGB tensor (2x height and width)
```

The initial model is deliberately small and export-oriented: two convolutions, ReLU, and PixelShuffle. It establishes a deployment baseline rather than SOTA image quality.

## Quick Start

Requirements: Python 3.10+, PyTorch 2.0+, NumPy, and Pillow. From this directory:

```powershell
python -m unittest discover -s tests -v
python -m benchmark.benchmark_model --height 64 --width 64 --warmup 10 --iterations 100
python -m tools.run_sr_image --synthetic-size 96x64 --output-dir results/p1_2
# Or use a local image:
python -m tools.run_sr_image --input path/to/input.png --output-dir results/custom
python -m tools.inspect_export_readiness --output docs/EXPORT_READINESS.md
python -m tools.run_pc_baseline --sizes 64x64 320x180 960x540 --warmup 5 --iterations 20 --threads 1
# Run with .venv-executorch, not the Phase 1 environment:
.venv-executorch\Scripts\python.exe -m tools.smoke_executorch
.venv-executorch\Scripts\python.exe -m tools.export_spatial_sr_portable
.venv-executorch\Scripts\python.exe -m tools.export_spatial_sr_xnnpack
.venv-executorch\Scripts\python.exe -m tools.export_spatial_sr_dynamic
# Non-mutating Phase 3 Android prerequisite audit:
.venv\Scripts\python.exe -m tools.check_android_environment
# Generate the ignored Android model asset before building the app:
.venv-executorch\Scripts\python.exe -m tools.prepare_android_model
# Read-only QNN/HTP readiness audit:
.venv-executorch\Scripts\python.exe -m tools.check_qnn_environment
# Inside WSL, source the reproducible local QNN/NDK environment:
source tools/qnn_env.sh
# From WSL, create the ignored static SM8550 HTP FP16 artifact:
bash tools/run_qnn_export.sh
# Build the external Android QNN runner, then deploy/run/verify on the connected phone:
bash tools/build_qnn_runner.sh
bash tools/run_qnn_on_device.sh
```

The image command saves `input.png`, `bilinear_2x.png`, and `neural_2x.png`. The synthetic source is generated by project code and has no external licensing dependency. The neural model still has deterministic random weights, so its output validates the pipeline only and is not a claim about SR quality. The benchmark is inference-only CPU timing, not an end-to-end mobile result.

```text
tests/       automated tests
benchmark/   reproducible benchmarks
android/     future Android app and native pipeline
assets/      licensed source media
results/     generated reports and outputs
tools/       later export/project utilities
docs/        specification, plan, and task ledger
```

## Roadmap

1. Spatial 2x SR on PC.
2. ExecuTorch export and parity.
3. Android CPU inference.
4. Qualcomm QNN / Snapdragon NPU.
5. FP32 / FP16 / INT8 comparison.
6. Vulkan preprocess/composite and transfer analysis.
7. Temporal reconstruction with history, motion vectors, and depth.
8. Comparative demo and end-to-end benchmark.
